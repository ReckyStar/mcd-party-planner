# 满减、凑单与券叠加计算规则

## 一、券与满减的区别

| 项目 | 优惠券 | 门店满减 |
|---|---|---|
| 来源 | `query-store-coupons` 或 `available-coupons` | `query-promotions`（仅团餐场景） |
| 门槛 | 部分无门槛，部分有 | 必有门槛 |
| 适用范围 | 按券规则，可能限品类或限门店 | `products` 字段明确列出，含"不包含"类型 |
| 可否叠加 | 同一订单可能限用一张 | 可能与券同时生效 |

**关键区别**：券是用户资产，拿到手就有；满减是门店规则，需订单金额达标才触发。输出方案时必须分别列出，不能笼统写"优惠 XX 元"。

## 二、必须先算门槛是否已达标

很多方案算错了，原因是把"有券"当成"能用券"。按下面顺序检查：

1. 读取 `query-promotions` 返回的每条规则，确认 `startTime`、`endTime` 覆盖当前时间
2. 核对 `products` 字段：`type=1` 表示包含，`type=2` 表示不包含，`type=3` 表示全部
3. 计算当前方案中参与该规则品项的小计金额，判断是否达到门槛
4. 未达标时不得把该优惠计入到手价

`promotionType=31` 是满额减，`33` 是订单折扣。`ruleCategory=30` 是满折/折扣，`40` 是满减。

**套餐陷阱**：门店满减常把套餐排除在外（`type=2`）。凑单时应优先加单点品项而非套餐，否则可能白凑。

## 三、凑单决策规则

凑单的核心问题是：加多少钱，多省多少，值不值。

按下面步骤判断：

1. **当前差额**：门槛金额 − 参与该规则的品项小计
2. **候选品项**：从 `query-meals` 返回中筛选，单价低于差额、且属于规则适用范围的品项
3. **判断净收益**：

```
净收益 = 触发满减后的减免金额 − 加购金额
```

`净收益 > 0` 才建议加购。`净收益 ≤ 0` 时明确告诉用户不值得凑。

## 四、凑单结论的写法

必须给出明确结论，不能含糊。参考写法：

**值得加购：**

> 凑单建议：当前小计 196 元，距满 200 减 30 还差 4 元。加 1 份小薯条（7 元）可触发 30 元减免，
> 净省 23 元，建议加上。

**不值得加购：**

> 凑单建议：当前小计 263 元，已超过满 200 门槛，加购无法触发更多优惠。若想再省，
> 只能换更低价的品项，但会减少份量。

**无法凑单：**

> 凑单建议：门店满减规则未包含在售套餐，当前小计 196 元，按现有品项无法触发，
> 建议按此方案下单。

## 五、人群替换规则

替换方案时必须同时更新总价，不得沿用原价。

| 人群需求 | 处理方式 | 注意 |
|---|---|---|
| 不吃辣 | 换用无辣品项 | 用 `query-meal-detail` 确认可选项，不要凭名称推断辣度 |
| 儿童 | 查 `list-nutrition-foods` 选儿童餐 | 儿童餐价格与营养数据以工具返回为准 |
| 素食 | 查门店是否有对应品项 | 门店无供应时如实说明，不虚构 |
| 忌口过敏 | 说明门店品项实际含有的配料 | 依据 `query-meal-detail` 返回，不猜测 |
替换后必须重新调 `calculate-price` 验算，并在输出中说明替换项与差价。

## 六、人均计算

```
人均 = 到手价 ÷ 人数
```

到手价是扣除券与满减之后的金额。四舍五入保留两位小数。

若原价人均和到手人均差距明显，在输出中同时给出两个数字，让用户直观看到优惠力度。

## 七、常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 自行加总品项价格 | 与实际结算价不符 | 一律用 `calculate-price` 返回值 |
| 把有券当成能用券 | 到手价虚低，用户到店发现用不了 | 先验门槛和适用范围 |
| 非团餐场景查 `query-promotions` | 工具报错 | 跳过并说明原因 |
| 团餐算价前未取助餐服务码 | `calculate-price` 缺 `gmServiceCode` | 先调 `query-meal-assistance` |
| 猜营养数据 | 数据不准确 | 只用 `list-nutrition-foods` 返回的全量表 |
| 凑单时加套餐 | 套餐常被满减排除，白花钱 | 凑单优先加单点品项 |
| 替换品项后沿用旧总价 | 人均和优惠金额全错 | 替换后重新验算 |
| 满减金额直接当作到手价 | 忽略券也可能失效 | 分别列出券与满减 |

## 八、数据缺失时的处理

| 缺失内容 | 处理方式 |
|---|---|
| 门店无促销规则 | 说明"该门店当前无满减规则，仅可使用优惠券" |
| 券无门槛信息 | 按券面规则处理，不假设门槛 |
| 菜单不含目标品项 | 如实说明门店当前不供应，给出替代建议 |
| 营养数据缺失 | 只标注"暂无营养数据"，不估算 |

任何情况下都不用记忆或估算填补价格与优惠数据。缺就是缺，直接说出来。
